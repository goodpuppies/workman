# Workman 0.5.0

0.5.0 is a breaking release: integers, the library layout, WON and pakman's file formats all
change. pakman state written by 0.4.x must be converted by hand (see below).

## Breaking changes

- **Integers.** `I32` is a checked signed 32-bit integer type. SubsetML reads bare Workman
  integer literals as `int`, so translated code and frontend-v3 use `I32`.
- **Library layout.** The SubsetML Basis is the WM Basis, imported as `"basis/…"`; std modules
  are imported as `"std/…"`. std's Result, Option, List and ListPair are built on the Basis, with
  renames such as `Option.withDefault` → `getOr`. Only `std/` modules are open in every program;
  an imported library module is exactly what its file declares.
- **WON.** WON is the Basis module `SubsetWon`. Text values are their UTF-8 bytes
  (`Text of char list`); `Won.textString` and `SubsetText` convert to and from host text.
- **pakman recipes import only `"pakman/…"`.** The recipe API (`model`, `package`, `finders`,
  `io`, `repository`) and the modules it shares with pakman (`plan`, `refs`, `won`, `text`, `fun`)
  are a library embedded in the compiler. Relative imports into `tooling/pakman/src` and
  `js.module` imports of pakman's `host.ts` no longer work: use `captures`, `capturesAll`,
  `jsonKeys`, `jsonField` and `jsonTextOr` from `"pakman/finders.wm"` (they return lists and
  `String` errors) and `fetchText`, `headInfo`, `runCapture`, `series` from `"pakman/io.wm"`.
- **pakman formats.** The package protocol is WON, protocol 11. The lock, generations, the
  applier's ownership record and plan file, and dependency graph snapshots are WON files. Store
  hashes cover WON text, so every store path changes and every package rebuilds.
- **pakman finders.** `ReleaseOptions.ref` returns `Option<String>`; `None` drops the release.
- **pakman configuration.** WM user configuration and `pakman add-dir`.

### Converting pakman state

There is no migration code. Convert each profile's `lock.json`, `generations/N.json` and graph
snapshots, and each root's `var/lib/pakman/owned.json`, to the WON documents above
(`Lock<protocol = 3>`, `Generation<protocol = 1>`, `Graph<protocol = 3>`,
`Owned<protocol = 1>`), keeping the JSON files as backups. Then run `wm pakman update` to rebuild
the store under the new hashes.

## Other changes

- Self tail calls through known function wrappers become loops.
- Inferred record types are shown after record literals.
- Structural equality no longer recurses, so long lists compare without overflowing the stack.
- `pakman/` modules are type-checked only for programs that import one, so other programs'
  startup time is unchanged.
