# Workman 0.5.1

This patch fixes source launchers and Windows module and editor paths.

- The source installer records the absolute Deno executable path, so installed Workman
  commands can start when Deno is absent from `PATH`. Windows launchers preserve spaces,
  percent signs and exclamation marks in runtime and checkout paths.
- JS reflection decodes escaped import specifiers and passes absolute paths to Deno as
  file URLs. Import-map types remain authoritative on Windows.
- Imported constructor targets support drive-letter and URL colons. Packages whose
  declarations are exposed only through `exports` can be reflected from Deno's npm cache.
- Editor cache keys share virtual POSIX paths and their file URIs on Windows. Canonical
  Windows paths use a consistent drive-letter case, and virtual module lookups accept
  forward-slash path keys.
- Release generation keeps portable source paths in semantic snapshots. Windows tests
  use native paths, escaped fixture strings and executable suffixes. GPU rendering tests
  retain their assertions while using a fresh Deno process per Windows case to avoid
  native device reinitialization failures.

Re-run `deno task install --force` from the source checkout to replace an existing `wm`
launcher. Reinstall if the recorded Deno executable moves. Launchers generated by
`deno install -g`, including `wmr`, remain managed by Deno and may require Deno on `PATH`.
