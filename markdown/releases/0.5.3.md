# Workman 0.5.3

Draft: not released yet.

This release adds effect taint, lighter syntax and default library pervasives, expands C and
JavaScript interoperability, and fixes several cases where programs silently did the wrong thing.

## Changes that can affect existing programs

- `&&` and `||` now short-circuit, following the derived forms of `andalso` and `orelse` in the
  Definition of Standard ML. The right operand runs only when the left one doesn't decide the
  result, so a right operand kept only for its side effect may no longer run. On `Result` or
  `Task` operands, `&&` and `||` still go through `map2` and run both sides.
- A `main` that ends with an `Err`, from a failed `Task` or a plain `Result`, now prints
  `error[runtime.main-failed]: main failed with <value>` and exits with code 1. It used to exit 0.
  `Ok(Err(x))` still counts as success.
- Library names such as `map`, `length`, `floor` and `not` are now bound by default. A name your
  program declares or imports itself takes priority. Inside `@gpu` lambdas these names are hidden,
  so `floor` and `length` mean the GPU builtins.
- Named match functions require whitespace or call parentheses before an argument. Compact
  adjacency is now rejected, where it used to split into separate top-level expressions.
- `Option` now comes from the shared SubsetML Basis. Constructor and FFI identities are preserved.

## Language

- Effect taint: the type system now tracks effects with `!`, as in `Void -> Number!`. Foreign
  calls and `Panic` introduce it, and it follows values through ordinary inference, including
  callbacks: `h(f)` is `Number!` only when `f` is effectful. `!` is informational for now and
  rejects nothing. See `docs/effect-taint.md`.
- Light lambdas: a single parameter may omit its parentheses and a body may be any expression, as
  in `x => x * x`.
- Grouped pattern lambdas such as `(Ok(x) => x)`, also usable in pipelines.
- Argument placeholders, braceless anonymous matches, match arms with expression bodies, and
  Boolean pipelines into `if`/`else`.
- Record fields may hold an unnamed nested record literal, and named record literals accept long
  names.
- Integer literals are inferred from their numeric context, and exact `Int64` and `Word64` values
  are preserved through parsing, inference, patterns and native calls.

## Library

- Default pervasives from the shared Basis and `std`, including `map`, `filter`, `foldLeft`, `head`,
  `length`, `getOr`, `not`, `chr`, `ord`, `explode`, `implode`, `size`, `str`, `floor`, `round`,
  `vector` and `toList`, plus `Order`, `Less`, `Equal` and `Greater`.
- Portable JSON trees with strict parsing, encoding and checked traversal, which report byte offsets
  and field paths.
- `String.toList`, `Result.filter`, and portable text, decimal parsing, padding and path helpers.
- `std` modules can import public library paths such as `basis/list.wm`.

## Interoperability

- C: reflection of widths, enum values, nested struct and union layouts, and scalar fields, with
  explicit pointer and resource host modules. Resolved C and JavaScript imports call directly with
  fixed arguments when the arity is known, instead of building a tuple.
- JavaScript: foreign class and interface type arguments are now kept in the type system, so
  `Box<Number>` and `Box<String>` stay distinct.
- Annotations may omit foreign type arguments that have a default, so `let b: Buffer` works. Omitted
  arguments are inferred. Record fields still write them all.
- npm subpath imports such as `three/webgpu` reflect through the package's `exports` map, and a
  package without its own declarations takes them from `@types/<name>`.

## Tooling

- The language server shows `!` in hovers and inlays. A bare lambda `x => x + 1` now gets its return
  type as an inlay.
- REPL: cursor editing, input history that persists between sessions, and recovery of the accepted
  session after parse, type and runtime errors.
- Diagnostics suggest the closest record for an unmatched record literal.
- New `docs/syntax-cheatsheet.md`, mirroring the SML syntax reference with WM equivalents.

## Fixes

- A line comment on the last line of a file with no trailing newline no longer crashes the compiler
  by exhausting memory.
- A constructor used as a pipe stage, as in `value :> Some`, no longer fails at runtime with a
  `ReferenceError`. This affected user-declared constructors too.
- Unfinished lambdas with parameters, such as `let id = (x) => { x`, recover as one lambda again.
  This fixes misleading errors while typing. The regression was introduced during this release's
  development, so it doesn't affect 0.5.2 users.

## Examples

- Unix and Windows C socket servers under `examples/server`, and Effect v4 server and sequencing
  examples under `examples/effect-ts`.

## Performance

Effect taint adds about 3 to 5% to a fresh `wm check` on real programs.
`markdown/issues/inference-performance-plan.md` has the measurements and the planned parser and
library cache work.

Update both the CLI and VS Code extension to 0.5.3. Source-checkout users should restart the Workman
language server after updating.
