# Workman 0.9.0

This release makes npm the default way to get wm, adds deferred carrier-aware list traversal,
makes collection counts and indexes `Int64` by default, and gives integer parsing and checked
arithmetic a uniform `Result` API. It has breaking changes; see Migration below.

## npm without Deno

- `npx @goodpuppies/workman run hello.wm` and `npm install -g @goodpuppies/workman` give the
  whole toolchain. The npm package's binary embeds the Deno runtime, and `run`, `watch`, `repl`,
  `test`, `pakman`, `problems` and `wm sml` now work in it with no Deno installed; before, it
  rejected them.
- JS/TS reflection no longer calls a Deno CLI: Deno's declarations are generated at build time and
  `@types/node` is embedded, which also fixes `node:` module imports in the npm build.
- Not yet in the npm build: programs that import npm, JSR or remote packages, and
  `wm compile --executable`. Both report this and point to the Deno/JSR installation, which keeps
  working as before.

## Carrier-aware list traversal

- `List.generate(Result, check) :> List.collect(Primitive.filter)` runs a carried check per
  element and collects the answers with a pure consumer. `Primitive` provides `filter`, `map`,
  `filterMap`, `concatMap`, `find`, `findMap`, `exists`, `all`, `takeWhile`, `partition` and
  `lastOr(fallback)`; a custom consumer is an ordinary `Primitive.Consumer` record.
- Checks run left to right. A carrier failure, or a decisive answer from `find`, `exists`, `all`
  or `takeWhile`, stops before the next check. Long synchronous and Task traversals are stack
  safe.
- `List.generateState(Result, initial, check)` threads a checked state, so a checked fold is
  `:> List.generateState(Result, 0, Int64.checkedAdd) :> List.collect(Primitive.lastOr(0))`.
- Carrier records have a new `loop` operation (`Result.loop`, `Task.loop`, `Monad.loop`), and
  `Monad.Step` is `Continue<state> | Stop<output>`. Custom carriers need a `loop` field.
- `List.annotate` keeps `(input, answer)` pairs inside the carrier; `List.concatMap` is the pure
  flattening map; `List.unfold` builds a list from a state.

## Integers and collection widths

- Unsuffixed counts and indexes are `Int64`: `List.length`, `repeat`, `splitAt`, `at`, `take`,
  `drop`, `tabulate`, `String.size`/`extract`/`substring`, `Text.size`/`extract`/`substring`
  and the `StringCvt` padding functions. Each has a `32` variant with the Int32 contract
  (`List.length32`, `String.size32`, ...). `wm sml` exposes only the `32` variants for now.
- `Int32` and `Int64` share `fromString`, `parseDecimal`, `parseNatural`, `checkedAdd`/`Sub`/`Mul`,
  `fromReal64`, `toString`, `minimum` and `maximum`, all returning `Result` with typed errors.
  `Int64.toReal64` returns `Result` and reports `PrecisionLoss`; `Int64.fromInt32`/`toInt32`
  convert at width boundaries.
- `Int32.range`/`Int64.range` enumerate inclusive ranges without overflow at the maximum, and
  `foldRange` folds one without building a list.
- `List.sumWith(Int32)`/`productWith` fold with a numeric domain's arithmetic.

## Syntax

- A constructor arm can hand its payload straight to a pipeline: `Err => :> handle` means
  `Err(payload) => payload :> handle`.
- `message :> Panic` panics with the piped message.

## Diagnostics and runtime

- A failed `Result.debug` reports `runtime.result-debug` at the user's call site, skipping
  library frames, in programs and the REPL.
- Pipe and return-annotation conflicts highlight both conflicting origins in the editor.
- Library error types are named by their public module (`List.Error`, `Int64.Error`), and a
  nullary constructor used as an error mapper suggests the payload it is missing.
- Pattern-match completeness keeps wildcard rows during constructor specialization, replacing a
  conservative second pass.

## Migration

- Code that used counts or indexes as `Int32` either annotates `Int64` or switches to the `32`
  variants.
- `Int32.checkedAdd`/`checkedSub`/`checkedMul` and `Int32.fromReal64` return `Result` instead of
  `Option`. `Int64.fromString`, `fromReal64` and `toReal64` return `Result` instead of throwing.
- Custom `Monad.Carrier` records need a `loop` field.
