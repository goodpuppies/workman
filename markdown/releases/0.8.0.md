# Workman 0.8.0

This release aligns Workman's numbers, names and Basis with Standard ML, adds private declarations
and the `wm sml` backend, and gives TypeScript first-class access to Workman modules. It contains
breaking changes; the upgrade steps below list each one.

## Numbers

- The numeric types are `Int32`, `Int64`, `Real32`, `Real64` and `Word8`–`Word64`. Each is a
  namespace holding its type and operations (`Int32.Int`, `Real64.Real`), and a bare namespace in
  type position means its `Self` type, so programs write `Int32` and `Real64`.
- Integer literals default to `Int32` at declaration boundaries; decimal literals are `Real64`, or
  `Real32` where the context asks for it.
- Arithmetic follows the Definition's Appendix E. `+ - *`, the comparisons and `%` take every
  numeric type, `/` takes the reals, and unary `-` the signed types. An operator nothing decides
  takes its class default at its declaration, as in SML: `(a, b) => a + b` is
  `(Int32, Int32) -> Int32`, and `/` is `Real64`. `@gpu` code still defaults to `Real64`.
- `%` truncates toward zero for every type. An integer `%` by zero panics instead of giving `NaN`,
  and `-2147483648 % -1` is `0`. `Int32.div` and `Int32.mod` remain the flooring forms.
- Integer literal patterns match integers and words only, as in SML. Compare a real with a
  computed pattern, `=(0)`, or with `==`.
- `Int32`'s conversions and checked operations (`minimum`, `maximum`, `checkedAdd`, `checkedSub`,
  `checkedMul`, `toReal64`, `fromReal64`, `toString`) come from the Basis; only `div` and `mod`
  remain compiler operations.
- A type error now shows an undecided literal's possible types (`Real64.Real or Real32.Real`)
  instead of a type variable.

## Basis and standard library

- The SubsetML Basis owns its names. Every public Basis module is a namespace programs and the REPL
  use without imports (`Bool`, `Char`, `StringCvt`, `OS`, `Won`, `Text` and others). A std module
  named like a Basis module (`List`, `Option`, `Result`, `String`, `ListPair`) re-exports it and
  only adds names.
- `Option` and `Result` are defined once, in the Basis. `Carrier`, `Applicative` and the `Monad`
  functions are the Basis module `SubsetMonad`, which `std/monad.wm` re-exports.
- `Monad.map`, `Monad.mapErr` and the new `Monad.andThen` and `Monad.traverse` take the carrier
  value first, so a pipeline supplies it: `value :> Monad.map(Result, f)`. `Monad.traverse` stops
  at the first failure and runs in constant stack.
- Collections use one modern name per operation (table below). Fold callbacks are element-first,
  `(x, acc)`, in both directions; `Map.foldLeft` and `Map.foldRight` pass `(key, value, acc)`.
- `Option.isNone`, `Result.isErr` and `Result.fail` complete the predicates and constructors.
- Lists display as `[1, 2, 3]` everywhere: `print`, `Text.of`, template strings, the REPL and
  `main failed` messages.

## Language

- `private` before a top-level `let`, `let rec … and …`, `type` or `record` hides it from
  importers. A private type's constructors are private, and a public binding whose type mentions a
  private type is an error. `private` is a contextual keyword, so it stays usable as a name.
- `Nil` and `Cons` are the list's constructors and can't be declared again: list syntax always
  builds the built-in `List`, as SML forbids rebinding `nil` and `::`.
- Equality is no longer lifted over carriers. `Ok(1) == Ok(1)` is structural equality and `true`,
  and `Ok(2) == 2` is a type error.
- Named match functions accept explicit capture clauses.
- An annotation on a record literal no longer changes the literal's type: a function field keeps
  its taint, so `Monad.via Result f` with a JavaScript call `f` is marked `!`.

## `wm sml`

`wm sml <file.wm> <out-dir> [--mlton]` translates a program and its imports to portable Standard ML
with a `project.mlb`, and with `--mlton` builds it. The build runs the entry's `main`, as `wm run`
does. The translator is SubsetML's own reader, bundled with `wm`, so no native SubsetML is needed.
JavaScript and C imports, `@gpu` code, `Task` and lifted carrier operators have no translation.
A field access on an open record has none either: annotate the receiver with its record type.
`docs/sml-target.md` describes the profile and its limits.

## TypeScript and JavaScript

- TypeScript imports Workman modules directly through the content mapper, which projects records,
  JavaScript types and module exports.
- Library exports carry `Result` as `{ ok: true, value } | { ok: false, error }` and `Task` as a
  `Promise` of one, converting in both directions. `Option` crosses as an opaque value, built and
  read with the new `@goodpuppies/workman/interop` module.
- JavaScript FFI resolves through properties, dictionaries and installed packages, and imported
  constructors work as values.
- Long list literals compile to a flat array, so large tables no longer nest deeply in emitted
  JavaScript.

## Tooling

- `wm repl "code"` evaluates and exits with a status; `wm repl preload "code"` runs startup phrases
  for an interactive session.
- Helix and Zed use the published tree-sitter grammar, and the editor grammars know `private`.
- Declaration navigation survives type errors, and function collision diagnostics attribute their
  sources more precisely.

## Upgrade steps

Renames are hard renames, with no compatibility aliases.

| 0.7.0 | 0.8.0 |
|---|---|
| `Number`, `Float64` | `Real64` (`Real64.Real`) |
| `I32` | `Int32` (`Int32.Int`) |
| `Float32` | `Real32` |
| `std/real.wm` | `std/real64.wm` |
| `Number.div`, `Number.mod` | removed; use `Int32.div`, `Int32.mod` on integers |
| `I32.fromString` (whole input) | `Int32.fromString`, or `Int32.parseDecimal` for whole input |
| `viaError` (`Monad`, `Result`, `Task`, the `Carrier` field) | `viaErr` |
| `foldl`, `foldr`, `foldli`, `foldri` | `foldLeft`, `foldRight`, `foldLefti`, `foldRighti` |
| `app`, `appi` | `forEach`, `forEachi` |
| `sub` (vectors and slices) | `at` |
| `collate` (`List`, vectors) | `compareWith` |
| `Map.fold` (accumulator first) | `Map.foldLeft`, `Map.foldRight` with `(key, value, acc)` |
| `List.any`, `mapPartial`, `revAppend`, `null`, `app`, `hd`, `tl` | `exists`, `filterMap`, `reverseAppend`, `isEmpty`, `forEach`, `head`, `tail` |
| `Option.valOf`, `Option.app` | removed; `Option.forEach` |
| `Result.toBool` | removed; use `Result.isOk` |

Behavior changes to check:

- **Integer defaults.** Unannotated arithmetic and `%` now default to `Int32`. Annotate helpers
  meant for reals (`(x: Real64) => x * 2`). Code that mixed a defaulted helper with reals reports
  a type error rather than changing results.
- **List functions.** `List.length` returns `Int32`; `List.at`, `take`, `drop`, `tabulate`,
  `head`, `tail` and `last` return a `Result`. Fold callbacks take `(x, acc)`. The `ListPair`
  folds and predicates return `Err(UnequalLengths)` instead of stopping at the shorter list.
- **Literal patterns on reals.** Replace `0 => …` on a `Real64` with `=(0) => …`.
- **Monad stages.** Write `value :> Monad.map(Result, f)` rather than the curried form.
- **Custom carriers.** `Monad` functions read a full `Carrier`: a custom carrier writes all seven
  fields, stubbing the ones it doesn't support.
- **`Nil` and `Cons`.** Rename your own constructors with those names, or use the built-in list.
- **Lifted equality.** Unwrap carriers before comparing them with a plain value.
- **TypeScript callers** of library exports read `result.ok` and `result.value` or `result.error`
  instead of the constructor objects.

Update the CLI and VS Code extension together, and restart the language server and open REPL
sessions after updating.
