# Workman 0.5.2

This patch fixes Windows language-server lookups and reduces editor analysis overhead.

- Windows file URIs with encoded lowercase drive letters now select the same project and
  module interfaces as compiler paths, restoring hover and other semantic queries.
- Opening an unchanged dependency already present in an analyzed project reuses that
  snapshot instead of invalidating and rebuilding the project.
- Ordinary language-server hovers use existing type facts. The optional `unannotated:`
  comparison is disabled by default because it requires speculative project analysis.
  Enable `workman.hover.unannotated` in VS Code, then restart the language server, to
  restore the comparison. Standalone servers accept `WORKMAN_UNANNOTATED_HOVER=true`.
- Semantic scopes and completion names retain lexical-scope sharing instead of repeatedly
  copying scope maps and sorting the same names for individual syntax nodes.
- Diagnostic type snapshots preserve their original shapes but render text only when
  diagnostic support is requested, avoiding discarded formatting on successful constraints.
- Nominal-type registries share storage until a registration requires an independent copy.
  Empty and single-origin provenance lists avoid unnecessary deduplication bookkeeping.

Performance measurements on one Windows `atview` workload showed lower inference and
semantic-snapshot construction costs. These are workload-specific improvements, not an
incremental-inference redesign; edits still reanalyze affected projects.

Update both the CLI and VS Code extension to 0.5.2. Source-checkout users should restart
the Workman language server after updating.
