# Workman 0.6.5

This release extends pipelines to ordinary record fields and implicit-input lambdas, improves REPL
result highlighting, and explains failed field access through authored type-origin diagnostics.

- Read ordinary record fields with `value :> .name`, follow nested paths with
  `value :> .outer.inner`, and call function fields with `value :> .callback(argument)`. Record
  stages preserve normal types, field constraints, effects, and evaluation order. JavaScript
  receiver reflection retains its existing behavior.
- Write implicit-input pipeline lambdas such as `=> :> add(1)` or `=> { :> first() :> second() }`.
  Nested pipelines keep independent inputs, and the formatter preserves the shorthand. Ordinary
  bare-arrow lambdas still take `Void`.
- Interactive REPL result reports now highlight declaration and inferred types without recoloring
  program output. Binding names, `<function>`, and `void` values stay plain; complete inferred
  types, including `where` constraints, use one type color. Piped sessions stay plain.
- Invalid record projections use an authored diagnostic with an **Origins** section. Reading a field
  from the result of `print` identifies the `print` call and its `Void!` return type. Imported
  origins retain their source locations. Shared cropped excerpts keep carets aligned on narrow
  terminals, including fields near the end of long lines.
- Experimental `pakman/files.wm` helpers provide verified downloads and ordinary archive extraction
  for runtime setup code. Downloads reuse matching local files and leave existing destinations
  intact on download or hash failure. Extraction requires the host's `bsdtar`.

Update the CLI and VS Code extension together. Restart the language server and open REPL sessions
after updating. Field access and space-call precedence are unchanged: use explicit grouping when
passing a computed field to a function, for example `print ((make()).name)`.

Known C-header limitation: pointers to records with unsupported private layouts, such as some libc
`FILE` implementations, can still fail during reflection. This release does not add bitfield layout
support. See the [tracked limitation](../issues/c-header-opaque-pointee-layouts.md).
