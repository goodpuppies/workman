# Workman 0.8.3

This patch makes `wm sml` faster. Translating and building a small Advent of Code day with
`wm sml day2.wm ./dist --mlton` went from about 6.3 s to about 2.4 s.

- With MLton on PATH, `wm sml` translates with a native build of SubsetML's reader. The package
  carries the reader's SML; the first run builds it once (about 15 s, with a note on stderr) into
  the Workman cache under `subsetml/`, keyed by the source, and later runs reuse it. Without MLton,
  or if that build fails, `wm sml` translates with the JavaScript reader as before.
  `WM_SML_TRANSLATOR=js` forces the JavaScript reader.
- The JavaScript reader is faster too: its lexer compares symbols in place instead of slicing the
  source, and the JS emitter gives functions that match on a tuple across several arms a direct
  multi-argument entry, so calls no longer build and take apart a tuple. A local function that is
  only called directly no longer gets the tupled wrapper at all.
