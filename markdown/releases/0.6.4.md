# Workman 0.6.4

This release adds inline nominal record annotations, native WON data literals, and local project
commands, with a fuller React example built through ordinary JavaScript interop.

- Declare named record schemas directly in type annotations, such as `Point{x: I32, y: I32}`.
  Repeated annotations reuse the visible nominal identity and check the schema. Explicit record
  redeclarations in the same scope are errors.
- Construct portable WON records, lists, and tags with `WON{...}` and `WON[...]`. Editor hovers
  describe authored tags, attributes, and values.
- Export typed commands from `pak.wm` and invoke them with `wm run dev`, `wm run build`, or other
  project command names. Commands support sequential WM and external executable steps, environment
  overrides, and explicit watched paths.
- The React example uses Deno import-map aliases, automatic rebuilds and browser reloads, reusable
  components, hook-local state, and declarative text/action/component bindings. The renderer is
  library code; no React-specific compiler syntax is required.
- Go to Definition follows reflected JavaScript imports, including Deno and DOM globals, to their
  TypeScript declarations.
- LSP invalidation now refreshes failed importing test contexts, preventing an old dependency error
  from overwriting current diagnostics.
- Reflected JavaScript callbacks preserve their declared arity, including callbacks passed to
  `Deno.serve`. Callable specialization and computed patterns also gain compiler and editor
  coverage.
- Testman is available through public library imports. Test execution preserves project
  configuration and handles termination cleanly.
- REPL function names follow the terminal foreground color for readability on both light and dark
  backgrounds.

Update the CLI and VS Code extension together. Restart the language server and open REPL sessions
after updating.

Project command watches rebuild and restart the command; browser reloads reset application state.
Tools must already be installed: project commands do not provision a development environment.
