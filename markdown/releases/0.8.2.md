# Workman 0.8.2

This patch makes `Result`'s std helpers work with `wm sml`.

- `Result.traverse`, `collectList`, `filter`, `map3` and `map4` were unbound under `wm sml`:
  `std/result.wm` imported a JavaScript-only helper, so the SML target fell back to the bare Basis
  `Result`. The module now translates whole.
- `Result.debug` stops through the new `Debug.abort`. On JavaScript nothing changes except that
  the typed-hole error points into `host/js/debug.wm`, with the `Result.debug` call under
  "Reached from". An MLton build prints `Result.debug: Err (the error has no portable display)` and
  exits with status 1, since SML cannot print a value of unknown type.
- `Result.all`, which works on `Js.Array`, moved to `JsArray.all`.
- A bare `Result` passed as an argument, as in `Monad.map(x, Result, f)`, is its carrier under
  `wm sml` too.
- `Result.map3`/`map4` and `Option.traverse`/`forEach` no longer compare the callback with itself
  in their match arms.
