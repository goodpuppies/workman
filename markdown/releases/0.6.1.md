# Workman 0.6.1

This release speeds up parsing, type checking and JavaScript reflection, and keeps interactive REPL
values alive between phrases.

## Performance

- The parser skips alternatives that cannot match, scans lexical syntax without unnecessary
  allocations, and resolves binary operator precedence from a flat chain. Generated parser rules
  call each other directly in one module.
- `wm check` skips editor-only analysis and unused environment dumps. Standard-library analysis
  no longer starts TypeScript reflection for string length, and only modules with unresolved FFI
  work go through additional inference passes.
- JavaScript reflection reuses compatible TypeScript programs and avoids unnecessary type checking
  and subprocesses.
- Effect taint and type-origin tracking avoid repeated flattening and deduplication.
- Emitted datatype values store their payloads directly in fields.

## REPL and tooling

- Each accepted REPL phrase executes once in a persistent child process. Earlier values and effects
  survive without replaying previous phrases. A failed phrase leaves the previous bindings intact.
- Parsed modules and module analyses are reused between REPL phrases.
- `wm run`, watch and REPL evaluation write generated programs to temporary storage instead of
  leaving output beside source files. Relative JavaScript imports still resolve from their source
  locations, and emitted programs retain npm import support.
- Project identifiers and launcher help consistently use `wm`.
- The published package includes the compiler's runtime files without unrelated example packages.

## Language and library fixes

- JavaScript globals retain their generic arity and share type identity across Workman modules.
  Reflection handles generic classes whose type arguments are omitted and namespace imports.
- Primitive defaults wait until JavaScript receiver information is available.
- Record fields can be read from an expression, such as `makeRecord().field`.
- `List.findMap` returns the first successful optional result.
- Examples were updated for the current JavaScript import behavior.

The explicit REPL Task wait operation remains a proposal; this release does not add `awaitTask`.

Update the CLI and VS Code extension to 0.6.1 and restart running language servers and REPLs.
