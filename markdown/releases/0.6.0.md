# Workman 0.6.0

This release adds re-exporting imports and nested modules, so `OS.Process` works as it does in
Standard ML, gives the Basis process and environment support, and turns the REPL into a proper
editor that has the usual Basis structures ready at the prompt.

## Changes that can affect existing programs

- `basis/process.wm`: `exit` now takes a `Status` instead of a `Bool`. Use `success` or `failure` in
  place of `true` or `false`, or `Status(code)` for a specific exit code.
- Basis modules that use `SubsetOptionValue` unqualified now re-export it, as SML's `open` does:
  `bytes`, `list`, `option`, `result`, `sml_escape`, `utf16_source`, `won`, `won_parser` and
  `won_syntax`. A `from "basis/list.wm" import *;` now also brings in `Some` and `None`, with the
  same identity as the built-in ones.
- A whole number returned from `main` is now the program's exit code, so a `main` that happened to
  end in a nonzero number now exits nonzero. `main` returning a Task's `Ok(n)` still exits 0.
- `wm` with no arguments starts the REPL.
- `wm run` no longer prints `error[runtime.exit]` when a program exits with a nonzero status and no
  error message. The exit status is unchanged.

## Language

- `export from` re-exports what an import brings in. Plain imports stay private in every form:

  ```workman
  export from "./x.wm" import *;            // SML: open X
  export from "./x.wm" import * as P;       // SML: structure P = X
  export from "./x.wm" import { f as g };   // SML: val g = X.f
  ```

  The namespace form gives real nested modules, including types and patterns, as in
  `OS.Process.value`. `export` isn't reserved, so it's still usable as a name elsewhere. See
  `examples/reexport/`.
- Effect taint keeps its link through a callback's concrete result, so a value that came from a
  path that can panic now shows `!`. `!` is still informational and rejects nothing.

## Library

- `from "basis/os.wm" import * as OS;` gives the Basis `OS` structure, with `OS.Process` and
  `OS.Path`.
- `OS.Process` gains `system`, `getEnv`, `Status`, `success`, `failure`, `isSuccess` and `terminate`,
  so running commands no longer needs the Deno or C FFI.
- A process status is `Status(code)`, so a program can choose and read exit codes:
  `OS.Process.exit(OS.Process.Status(3))`. `success` and `failure` still work. The SML Basis keeps its
  status abstract, so this is an addition to it.
- `host/c/pointer.wm` gains `fromBytes`, the address of a JS typed array, for handing it to C.

## Tooling

- The language server marks an import when the module it reaches doesn't compile. Hovers and inlay
  hints in that file now return nothing rather than failing as requests.
- The REPL prompt is a multi-line text box that highlights input as you type, closes brackets and
  quotes, and shows a progress bar while loading.
- REPL sessions start with `OS`, `Bool`, `Char`, `Int`, `StringCvt`, `Io` and `Text` available
  without imports. They're ordinary imports, so a later import of the same name shadows them.
- New REPL commands `:help` and `:type`, a `quit()` function, a configurable prompt, and lists
  shown in list syntax. Highlighting uses Workman's own colors by default.
- Inlay hints wait for the first language server analysis, rather than showing a stale result just
  after a restart.
- Generated Basis, parser and wmslang files now say they are generated.

## SubsetML

- SubsetML gains a narrow structure alias, `structure P = X`, only at the start of a `struct` and
  only naming a whole program structure. It translates to and from `export from ... import * as P`.
- SML `open` translates to `export from ... import *`.
- `&&` and `||` translate to `andalso` and `orelse`.

Update both the CLI and VS Code extension to 0.6.0. Source-checkout users should restart the Workman
language server after updating.
