# Current state

Recorded on 2026-09-28 from the source tree.

## Where the basis lives

| Piece | File | Contents |
|---|---|---|
| Primitive type inventory | `src/basis_manifest.ts` | `BASIS_TYPES` (identity, arity, equality, profiles, constructors), `BASIS_OPERATORS`, `BASIS_VALUES`, `BASIS_INTRINSICS` |
| Value schemes | `src/types_basis.ts` (~890 lines) | `print`, pervasive constructors, `Task.*`, `Json.assert`, `Dict.*`, `Table.*`, `Word*`, `Word8Vector*`, `Bytes.*`, `PackWord*`, `PackReal*`, `Float*`, `Byte`, `Js.Array.*`, and the GPU value catalog |
| Basis artifact | `src/initial_basis.ts` | `InitialBasis` per profile (`kernel`, `default`) built from the two files above |
| Runtime | `src/core/emit_prelude.ts` (~950 lines) | JavaScript implementations as string literals: `print`, `__wm_show`, operators, `Task`, `Word*`, `Word8Vector`, `Word8VectorSlice`, packing, `Bytes`, … |
| Library sources | `std/*.wm` | `binary`, `list`, `map`, `monad`, `option`, `result`, `task`, `traverse` |
| Embedded sources | `src/generated/assets.ts` | Each `std/*.wm` file as a string export, generated by `scripts/generate_assets.ts` |
| Library loader | `src/standard_library.ts` | Hard-coded `standardModules` list with aliases; inference; `standardRuntimeGraph` |
| Program assembly | `src/compiler.ts` (`coreProgram…`) | Compiles std as a separate graph and merges it into the user program |

There is no `basis/` directory. Layer-1 material that exists (`Word8`, `Word8Vector`,
`Word8VectorSlice`, `PackWord*`, `Byte`) is defined entirely in TypeScript, with its runtime in the
prelude string.

## What adding something costs

### A new std module

1. Write `std/foo.wm`.
2. Add an entry to the hard-coded list in `scripts/generate_assets.ts`.
3. Regenerate `src/generated/assets.ts`.
4. Import the new export in `src/standard_library.ts` and add a `standardModules` entry with its
   namespace alias.
5. Place that entry after every std module it imports. `inferStandardModule` throws
   `standard import … must precede …` otherwise.

### A new primitive (for example a `Word8Vector` function)

1. A type in `BASIS_TYPES` if the primitive introduces one.
2. A scheme in the matching `add…Values` function in `src/types_basis.ts`.
3. A JavaScript implementation inside the prelude string in `src/core/emit_prelude.ts`.
4. Sometimes a `BASIS_VALUES` entry giving the runtime name.

Nothing checks the JavaScript in step 3 until a program calls it.

## How std is compiled and linked

- **Inferred per process.** `loadStandardModules` parses and infers every std module from its
  embedded source the first time it's needed in each process, then caches the result in a promise.
- **A separate graph.** `standardRuntimeGraph` builds a `ModuleGraph` for std alone, with emit names
  `__wm_std_<Alias>`. `coreProgram` in `src/compiler.ts` compiles that graph separately and merges
  it into the user program: module order, module maps, constructors, and nominal facts
  (`mergeStandardNominalFacts`, which also patches constructor references in user facts).
- **Host and source halves.** `composeInitialStructure` combines the compiler-defined structure of
  a name (for example the twelve TypeScript-defined `Task` values) with the std module of the same
  alias using `modifiedStaticEnv`. At runtime, a namespace with host members gets a separate
  `__wm_basis_<Alias>` object (`basisName`, `basisMembers`) next to the compiled std module.
- **Special identities.** Std values get `standardValueId(modulePath, name)` identities, and
  tooling refers to some by path (for example `src/lsp/unused_diagnostics.ts` looks up
  `std/result.wm` `debug`).

## Known problems attributable to this organization

- `issues/FIXED-std-namespace-adt-constructors-unusable.md`: qualified constructors of a std datatype
  (`Binary.Bounds`) crash in patterns and fail at runtime in expressions, while the same shape works
  for a user module. The std path's separate constructor and nominal-fact merge is the likely cause.
- Host types (`Js.*`, `Gpu.*`) share `BASIS_TYPES` with `Number` and `Bool`, so the compiler's layer
  0 and the host layers are not separable.
- Std is re-inferred from source on every process start, which adds to cold-start time
  (`../cold-start-performance.md`).

## Mechanisms that already exist and can be reused

- **Local JavaScript modules with manual types.** `from js.module("./x.js") import unsafe { f: T }`
  gives a `.wm` module a trusted, manually typed binding to a local JavaScript file
  (`docs/jsffi.md`). `unsafe` imports compile to direct calls with no `Result` wrapping.
- **Ordinary module graph and identity.** The module update's `ModuleId`, graph discovery, and
  per-module interfaces, which library modules can join instead of using a parallel path.
- **Profiles.** `kernel` and `default` in `src/initial_basis.ts`, which map onto "layer 0 only" and
  "all layers".
